# OB — Observabilidade (Java)

Padrões do time para a stack Java nesta família de slots, de propriedade do `prime-core/coding-standards`. Lidos junto com o índice, `references/defaults-java.md`, que guarda como ler as marcas (Spring), (Boot 4) e (Java 21+), a Plataforma e a Toolchain do time. As definições dos slots estão no arquivo de mesmo nome em `references/convention-slots/`.

- **CS-OB-1** — Somente SLF4J, mensagens parametrizadas (`log.info("order confirmed {}", id)`) — nunca concatenação. Saída estruturada pelo suporte nativo do Spring Boot: `logging.structured.format.console=ecs` (ou `logstash`, conforme o coletor do projeto) **(Spring)**, sem encoder montado à mão. `ERROR` = precisa de um humano esta noite; `WARN` = degradado mas tratado; `INFO` = aconteceu um evento de negócio; `DEBUG` = diagnóstico, desligado em produção. *Razão:* nível com significado e formato padrão são o que torna alerta e busca confiáveis. *Verificação:* regra Semgrep para concatenação em log; revisão dos níveis.
- **CS-OB-2** — W3C Trace Context (`traceparent`) em toda requisição recebida, mensagem consumida e chamada de saída; `traceId` e `spanId` no MDC de cada linha. Micrometer Tracing com OpenTelemetry e exportação OTLP — `spring-boot-starter-opentelemetry` **(Boot 4)** **(Spring)**. *Razão:* um formato só, para que uma requisição seja seguida através de todos os serviços. *Verificação:* teste de integração que confere o cabeçalho propagado numa chamada de saída.
- **CS-OB-3** — Nunca registrado em log: senhas, tokens, chaves de API, cabeçalhos de autorização e todo dado das classes `credencial`, `sensível`, `financeiro` e `pessoal` (`CS-SC-6`) — CPF/CNPJ, número de cartão, endereço, e-mail e afins —, nem corpos completos de requisição ou resposta que os carreguem. Um tipo que guarda um campo protegido nunca chega a um log pelo seu `toString()`: o campo é mascarado no tipo. *Razão:* o log é copiado, retido e lido por muito mais gente que o banco. *Verificação:* teste que captura os logs dos cenários com dado protegido; teste do `toString()` mascarado.
- **CS-OB-4** — Toda integração de saída é cronometrada e contada: os clientes criados a partir dos builders auto-configurados já emitem a observação `http.client.requests` **(Spring)**, e um cliente construído à mão perde isso. Todo evento de negócio sobre o qual um envolvido perguntaria recebe uma linha `INFO` com os identificadores necessários para correlacioná-lo. Em áreas `crítica`, cada meta não funcional tem métrica e alerta, e os caminhos de erro têm contador. *Razão:* instrumentação sistemática em vez de lembrada. *Verificação:* revisão.
- **CS-OB-5** — Eventos de segurança — autenticação (sucesso e falha), autorização negada, mudança de privilégio, alteração de dado `sensível` ou `financeiro`, ação administrativa — vão para o logger dedicado `AUDIT`, separado do log operacional, em JSON com `event`, `actor`, `target`, `outcome`, `timestamp` e `traceId`, nunca com o dado protegido. Em áreas `crítica`, o destino é um armazenamento só de inclusão, com a retenção que o projeto declara. *Razão:* uma investigação precisa de uma trilha uniforme que o ruído operacional não afoga. *Verificação:* teste que confere o evento nos cenários de negação e de alteração.
