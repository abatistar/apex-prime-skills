# CN — Consistência

Lente do catálogo de critérios do `prime-core/quality-model`. Lida junto com o índice, `references/quality-criteria.md`, que guarda os níveis, o piso num relance, os perfis de criticidade e os IDs aposentados.

*Princípio: tornar o código previsível — aprender um padrão uma vez e confiar nele em todo lugar. Inconsistência é surpresa sistematizada.*

- **QM-CN-1 [NON-NEGOTIABLE] — Sem erosão.** Não se introduz uma segunda forma de fazer algo que a base já faz de uma forma estabelecida. Um padrão muda por migração declarada — novo valor, responsável, escopo e condição de conclusão, conforme o `prime-core/coding-standards` —, nunca um arquivo por vez. Meio antigo, meio novo é o pior estado. *Violação:* fora de uma migração declarada, a mudança traz um segundo estilo de tratamento de erro, de acesso a dados ou de chamada externa, ou uma segunda biblioteca para uma preocupação já atendida. *Não é violação:* seguir o novo valor dentro do escopo de uma migração declarada.
- **QM-CN-2 [NON-NEGOTIABLE] — O padrão local vence a preferência, nunca o piso.** No código existente, a forma como *esta* base faz algo vence a opinião sobre a forma "melhor". Primeira pergunta ao entrar num código: "como esta base faz isso?". O padrão local nunca vence o piso: um padrão que viola um inegociável ou um slot INVARIANT é dívida herdada (`QM-MT-1`), não padrão a seguir. *Violação:* escrever o fragmento novo no estilo preferido de quem escreve, diferente do entorno, numa área cujo padrão não está sob migração.
- **QM-CN-3 [CALIBRATED] — Quatro níveis de consistência.** Formatação → nomenclatura e convenções → padrões idiomáticos → arquitetura e conceitos. Quanto mais raso, mais mecanizável e menos importa; quanto mais profundo, mais importa e mais exige julgamento humano. Empurre o mecanizável para as ferramentas, para liberar atenção para os níveis profundos. *Tensão:* as convenções concretas de cada nível são do `coding-standards`; este critério remete a ele, não as inventa.
- **QM-CN-4 [CALIBRATED] — Consistência não é uniformidade cega.** Coisas que realmente diferem devem parecer diferentes — cuidado com a falsa simetria, igual na aparência e diferente no comportamento. Uma convenção é uniforme num momento, não para sempre. *Tensão:* a saída da consistência tola é a mudança deliberada e em bloco, nunca a erosão.
- **[AUTOMATE]** — Formatadores, linters, verificadores de tipos, convenções impostas no pipeline. Debate de estilo na revisão é dívida de processo: a ferramenta decide de forma impessoal, e a atenção humana vai para lógica e desenho.
