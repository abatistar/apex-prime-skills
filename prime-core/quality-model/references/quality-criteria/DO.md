# DO — Documentação proporcional

Lente do catálogo de critérios do `prime-core/quality-model`. Lida junto com o índice, `references/quality-criteria.md`, que guarda os níveis, o piso num relance, os perfis de criticidade e os IDs aposentados.

*Princípio: preservar o conhecimento que o código não consegue carregar.*

- **QM-DO-1 [NON-NEGOTIABLE] — Documentação não mente.** Documentação desatualizada é pior que nenhuma: uma armadilha ativa em vez de uma lacuna honesta. A documentação técnica vive o mais perto possível do que descreve — no repositório, versionada junto, alterada no mesmo PR; os documentos do processo (casos de uso, ITS, ADRs) vivem na raiz de documentos do projeto, que pode ter versionamento próprio. Prefira documentação que *não pode* mentir: testes, tipos, exemplos que rodam no pipeline. *Violação:* a mudança deixa um documento versionado junto com o código — README, contrato de API, comentário de documentação, exemplo — afirmando o comportamento anterior; um documento que pertence a outro papel (caso de uso, ADR) passa a ser contradito pela mudança sem que a divergência seja reportada a quem é dono dele.
- **QM-DO-2 [CALIBRATED] — Documente o porquê.** O código é a fonte de verdade do *como* e, se legível, do *quê*; o *porquê* — alternativas descartadas, restrições externas, armadilhas evitadas — é território da documentação. *Tensão:* a exceção legítima é a complexidade essencial — uma fórmula densa, o contorno de um defeito de terceiros.
- **QM-DO-3 [CALIBRATED] — Triagem.** Documente apenas o que o código não carrega **e** muda devagar o bastante para valer a sincronização. *Tensão:* documentação em excesso afoga o importante e multiplica a superfície que pode apodrecer; documentação de baixo valor e alta volatilidade é dívida pura.
- **QM-DO-4 [CALIBRATED] — Audiência definida.** Escreva para uma audiência — usuário da API, mantenedor, recém-chegado, operador — sem misturar os modos (tutorial, guia prático, referência, explicação). O "como rodar" funcional para o recém-chegado é o mais negligenciado e o de maior retorno. *Tensão:* registros de decisão são ADRs, de propriedade do `prime-core/its-contract` — este critério os referencia, não os redefine.
- **[AUTOMATE]** — Exemplos executáveis no pipeline; verificadores de links; contrato de API gerado a partir do código ou verificado contra ele.
